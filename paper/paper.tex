\noindent{\sffamily\bfseries\color{ink}Abstract}\par\smallskip
Can a finite program compute with infinitesimals while leaving their non-constructive mathematical interpretation unspecified? We study an interface that records only observations made during execution. Each accepted observation preserves the existence of a free-ultrafilter completion. Lean 4 proofs connect an executable periodic Laurent language to these completions and interpret each accepted finite adaptive run using one fixed completion. Standard-part extraction is sound and complete for a value shared by all remaining completions. Every such finite real value is rational and is found by the extractor. A generic compiler builds literal difference quotients for arbitrary rational polynomials at rational points with steps $c/n^k$, where $c\ne0$ and $k\ge1$. The extractor returns the ordinary derivative. A second, symbolic compiler handles finite vectors, general division, and elementary functions on explicit smooth domains. Lean proves that its Jacobian-vector products are standard parts of literal quotients for every compatible completion with a nonzero infinitesimal step. An adaptive example makes an observation discharge a necessary division condition: an infinitesimal step may be zero in some completions, so the program either establishes its nonzeroness or selects a fallback. Both accepted branches extract $12$ for the cubic at $2$. The implementation retains exact finite syntax without constructing an ultrafilter or truncating a series. Kernel replay checks exported instances. The result connects finite observations to two forms of infinitesimal computation: complete Laurent extraction and symbolic elementary differentiation. General sequence predicates and verified capture of arbitrary Python computations remain outside it.

\section{Introduction}

A classical existence theorem can justify a mathematical object without supplying executable data for it. This raises an operational question: what may a finite program do with such an object? Hyperreal arithmetic provides a concrete setting. Its ultrapower interpretation uses a free ultrafilter, while a particular calculation may inspect only a few comparisons and return an ordinary real number. Computing those observations need not determine the entire ultrafilter.

We investigate this separation through an executable interface. The program builds exact expressions for real sequences and records selected comparison sets. The runtime accepts a selection only after checking that the retained recurring indices remain infinite. A classical extension theorem then supplies a free ultrafilter containing the observations. This existence proof justifies the execution without becoming an algorithm that constructs its witness.

There are two distinct guarantees. First, an accepted execution has a compatible completion, so its choices can be read as observations of one mathematical object. Second, standard-part extraction returns exactly the finite values shared by every completion compatible with that execution. The first permits underdetermined choices. The second permits an ordinary result before all choices have been made. For example, $(-1)^n$ has completion-dependent sign, but $1+(-1)^n/n$ has standard part $1$ in every free completion.

The fact that a program makes finitely many observations is not sufficient for an algorithm. Those observations concern actual subsets of $\N$, and their consistency can itself require mathematical reasoning. Propositional satisfiability of opaque names does not establish it. We therefore distinguish the general semantic requirement from an executable instance: finite periodic rational coefficients, $n$, $1/n$, arithmetic, and division by nonzero rational monomials. On this language, exact normalization and comparison masks discharge the required obligations. Unsupported sequence predicates are outside this implementation.

The paper develops three connected results:
\begin{enumerate}[itemsep=3pt,topsep=4pt]
  \item A specification of finite observations and classical completion, with an explicit separation between existential consistency and executable decisions.
  \item Verified normalization, comparison, and state refinement for a periodic Laurent language, with sound and complete extraction of completion-invariant standard parts and fixed-completion semantics for accepted adaptive programs.
  \item Generic executable infinitesimal differentiation for rational polynomials, a symbolic derivative compiler for elementary vector functions, and an adaptive observation that establishes a necessary denominator condition. The quotient semantics applies to either accepted step choice.
\end{enumerate}
The extension theorem is classical supporting mathematics. The calculus identities are elementary. Their role is to make the connection between finite execution and a non-constructive interpretation precise and inspectable. We do not claim a new construction of the hyperreals, a general algorithm for ultrafilter membership, or a performance advantage over symbolic algebra.

\section{An Adaptive Infinitesimal Calculation}\label{sec:infinitesimal-case}

Let $\varepsilon(n)=1/n$, with any convention at $n=0$. Changing the convention at this single index does not affect any free-ultrafilter interpretation. For every positive real $a$, the inequality $0<\varepsilon(n)<a$ holds eventually. Consequently, in every free completion the represented quantity is positive, nonzero, and smaller than every positive real constant. Its standard part is zero. Standard part zero does not make the quantity itself zero.

Take $f(x)=x^3$, $x=2$, and define actual increments
\[
  \Delta x=\varepsilon,\qquad
  \Delta y=f(2+\varepsilon)-f(2),\qquad
  Q=\frac{\Delta y}{\Delta x}.
\]
The denominator is nonzero in each completion, so the quotient is meaningful. Exact algebra at every positive index gives
\begin{equation}\label{eq:cubic-quotient}
  Q(n)=\frac{(2+1/n)^3-8}{1/n}
      =12+\frac6n+\frac1{n^2}.
\end{equation}
Thus $Q(n)>12$ at every positive index, while $Q(n)-12\to0$. In every free completion,
\[
  Q>12,\qquad \st(Q)=12=f'(2).
\]
Here $Q>12$ means that the set of indices satisfying the inequality belongs to the completion. The limit statement uses the filter definition of standard part in Section~\ref{sec:background}.

This example makes the fraction interpretation precise. The finite increments $\Delta y$ and $\Delta x$ have a literal quotient. Its standard part is the derivative. The quotient is not equal to the derivative before taking standard part. No rule allowing arbitrary manipulation of differential notation is assumed.

\Needspace{12\baselineskip}
The public interface expresses the original quotient directly:
\begin{lstlisting}
from hyperreals import LeanResidueSystem

system = LeanResidueSystem()
epsilon = system.infinitesimal()
x = system.constant(2)
quotient = ((x + epsilon)**3 - x**3) / epsilon
assert quotient.standard_part() == 12
\end{lstlisting}
The returned value is an exact rational. The expression is sent to the verified normalizer without a precomputed derivative or limit certificate. Lean proves the sequence identity, positivity and infinitesimal properties, the completion-relative limit, and the ordinary derivative in \code{InfinitesimalCase}. The theorem \path{quotientExpr_denote} connects the actual expression tree to the stated quotient, and \path{quotient_extracts} checks the executable result by kernel reduction. For a literal field interpretation, \path{hyperreal_quotient_standardPart} proves the same standard-part equality in Mathlib's hyperreal field, using its distinguished positive infinitesimal. The companion strict-inequality theorem proves that this field element is greater than $12$. The script \path{scripts/infinitesimal_case.py} runs the public API and exports replayable instances.

\subsection{An Observation Establishes the Domain}

The forward calculation alone requires no discretionary observation. To make the observation mathematically necessary, instead consider
\[
  b(n)=\begin{cases}0&n\text{ even},\\1&n\text{ odd},\end{cases}
  \qquad h=b\varepsilon,\qquad g=bn.
\]
The step $h$ is infinitesimal in every free completion. It is exactly zero in completions selecting even indices and nonzero in those selecting odd indices. The represented reciprocal $g$ satisfies $hg=1$ only in the latter. The residue language represents $g$ using multiplication and a periodic table. Its inverse property is justified on the selected support.

The program queries $h=0$. A true answer retains even indices and replaces $h$ by the fallback $\delta=\varepsilon^2$. A false answer retains odd indices, keeps $\delta=h$, and licenses multiplication by $g$ as division by $h$. Figure~\ref{fig:adaptive-quotients} shows the two branches. The observation is a caller-proposed polarity checked against the remaining support, not evaluation at a sampled index or membership testing in a preselected ultrafilter.

\begin{corollary}[Observation-dependent derivative extraction]\label{cor:adaptive-derivative}
  Every accepted execution has one fixed compatible free completion. In every completion of its recorded trace, the selected step $\delta$ is nonzero and infinitesimal, its returned expression denotes the literal quotient $((2+\delta)^3-8)/\delta$, and that quotient has standard part $12$. The executable extractor returns $12$ on both branches. On the positive branch, the original $h$ has no multiplicative inverse.
\end{corollary}
\begin{proof}
  The accepted observation gives eventual equality $h=0$ or eventual inequality $h\ne0$ in the same completion. On the negative branch, the periodic indicator takes value $1$, so $hg=1$. On the positive branch, replacing $h$ by $\varepsilon^2$ establishes a nonzero infinitesimal denominator. The two resulting expression trees extract $12$ by kernel reduction. Fixed-completion realization then applies to the entire selected run. The declarations \path{selected_step_nonzero}, \path{selected_step_infinitesimal}, \path{accepted_quotient_correspondence}, \path{accepted_result}, and \path{zero_branch_has_no_inverse} in \code{DomainInfinitesimal} prove these obligations.
\end{proof}

Before the observation, the multiplication expression $((2+h)^3-8)g$ has standard part $0$ in even completions and $12$ in odd completions. It therefore has no shared finite standard part, as proved by \path{guarded_no_common_standardPart}. The zero branch cannot be repaired by cancelling $h$. Its fallback changes the step. This is the distinction between an infinitesimal quantity and an invertible infinitesimal quantity that the observation enforces.

The script \path{scripts/domain_infinitesimal_case.py} captures the two branches in fresh systems and exports their traces and expressions for kernel replay. Tests separately evaluate the formulas with rational arithmetic and check that the opposite observation is rejected after a branch has been selected. These concrete checks do not establish a compiler-correctness theorem for Python. The corollary quantifies over all accepted answer streams for the explicit Lean program.

\subsection{Generic Polynomial Differentiation}

The polynomial compiler accepts any finite list of rational coefficients and constructs the corresponding Horner expression. Given $P\in\Q[X]$, $a,c\in\Q$, $c\ne0$, and $k\in\N$ with $k\ge1$, it forms the original syntax
\[
  h(n)=\frac{c}{n^k},\qquad
  Q_{P,a,c,k}=\frac{P(a+h)-P(a)}{h}.
\]
No derivative value, expanded numerator, or convergence certificate is supplied to this compiler.

\begin{theorem}[Executable polynomial differentiation]\label{thm:polynomial-derivative}
  For every such polynomial, point, scale, and exponent, and every nonempty residue support $S$, the generated expression denotes the literal quotient at positive indices and
  \[
    \sthat_S(Q_{P,a,c,k})=P'(a).
  \]
  The returned rational agrees with the usual real derivative. Its standard part is $P'(a)$ in every compatible free completion.
\end{theorem}
\begin{proof}
  A recursive polynomial divided difference $D_{P,a}(h)$ satisfies the exact identity
  \[
    hD_{P,a}(h)=P(a+h)-P(a)
  \]
  even when $h=0$. Writing $P(X)=p_0+XR(X)$ gives the executable recursion
  \[
    D_{P,a}(h)=R(a+h)+aD_{R,a}(h).
  \]
  The same recursion proves convergence to $P'(a)$ whenever $h\to0$, and an independent differentiation proof identifies that value with the ordinary derivative. The specified $c/n^k$ is nonzero at positive indices, so cancellation identifies the divided difference with the literal quotient. Completeness of extraction, proved in Section~\ref{sec:verified-laurent}, converts this convergence proof into the claimed executable result on every nonempty support.
\end{proof}

The proofs are in \code{PolynomialDifferentiation}. The declaration \path{rational_polynomial_representable} covers every rational polynomial with a finite coefficient list. The declarations \path{quotientExpr_denote} and \path{quotientExpr_computes_derivative} connect the generated expression, its executable extraction, and the usual derivative. The more general \path{dividedDifference_standardPart_of_standardPart} requires only that the executable extractor return zero for the increment on the current support. It therefore handles represented increments whose infinitesimality becomes established after an observation, including increments that are zero on some active residues. That polynomial expression remains meaningful at zero. Calling it a literal quotient still requires a separate nonzero condition, exactly the obligation isolated by the adaptive case.

Computing an ordinary derivative does not require an ultrafilter, and symbolic algebra also obtains these values. The contribution is the proof connecting exact executable syntax, completion-dependent domain conditions, and an ordinary output that is invariant over the remaining completions.

\subsection{Elementary Functions and Vector Derivatives}\label{sec:differentiable}

The polynomial result uses a complete rational extractor. The differentiable language returns symbolic real expressions. Its syntax has rational constants, finitely many real variables, arithmetic including general division, negation, and $\sin$, $\cos$, $\exp$, $\log$, and $\sqrt{\mathord\cdot}$. A program $F:\R^n\to\R^m$ is a finite vector of these expressions. The domain predicate is compositional: denominators are nonzero, logarithm and square-root arguments are positive, and all subexpressions meet their own conditions. These are sufficient smoothness conditions. In particular, this language excludes the square-root boundary at zero.

The executable compiler $J(F,v)$ applies the usual chain rules and produces expression syntax for a Jacobian-vector product. Tangent expressions are evaluated at the base point and held fixed as the scalar step varies. Coordinate basis directions give the Jacobian, and a scalar output gives a gradient. The compiler receives no derivative or convergence certificate.

\begin{theorem}[Compiled elementary quotient]\label{thm:elementary-quotient}
  Let $F$ and $v$ be represented by the differentiable language and let $a$ satisfy the source and tangent domain conditions. The generated expression is defined at $a$ and evaluates to $DF(a)v(a)$. For every compatible completion $\PUF$ and sequence $h$ satisfying $h\to_{\PUF}0$ and $\{k:h(k)\ne0\}\in\PUF$,
  \[
    \st_{\PUF}\!\left(\frac{F(a+h\,v(a))-F(a)}{h}\right)
    = J(F,v)(a)=DF(a)v(a)
  \]
  componentwise. The perturbed source expressions satisfy their domain conditions eventually in $\PUF$.
\end{theorem}

\begin{proof}
  Induction on expressions proves Fr\'echet differentiability on the specified domain, correctness of the actual derivative compiler along differentiable input curves, and preservation of the domain by compilation. The domain is open. Applying the compiler theorem to $t\mapsto a+t\,v(a)$ identifies its value with $DF(a)v(a)$. The ordinary derivative theorem gives convergence of the literal difference quotient along the punctured neighborhood of zero. The two hypotheses on $h$ provide a map into that filter, giving the claimed limit in each completion. Openness gives eventual validity of the perturbed operations. No infinitesimal term is declared zero before division.
\end{proof}

The modules \code{DifferentiableCore}, \code{Differentiable}, and \code{DifferentiableInfinitesimal} implement this construction. The declarations \path{Expr.jvp_eq_fderiv}, \path{Expr.domain_jvp}, and \path{Expr.quotient_standardPart} establish its three main obligations. The Python adapter returns immutable expression syntax. Kernel verification proves that this actual output agrees with the formal compiler before instantiating its semantic theorem. Supplying a rational point additionally requests a kernel proof of the source, tangent, and result domains there. The domain tactic is incomplete. Failure leaves an obligation unresolved, without asserting that a derivative or standard part does not exist. Floating-point samples are labelled approximations and carry no error certificate.

For a concrete example, take
\[
  F(x,y)=\left(\sin(x)e^y,\ \log(1+x^2+y^2),\
    \frac{\sqrt{1+x^2}}{1+y^2}\right),\qquad a=(1,0),\quad v=(1,2).
\]
The module \code{DifferentiableExamples} proves
\[
  DF(a)v=\left(\cos(1)+2\sin(1),\ 1,\ \frac{1}{\sqrt2}\right).
\]
It then reuses the observation-dependent step from the preceding case. Either the observation establishes nonzeroness of the original step or the program replaces it by $1/n^2$. Every completion of either accepted trace gives this same vector standard part. This connection reuses the residue observation engine's step guarantee. It does not add elementary comparisons to that engine or pass an elementary quotient to Laurent normalization.

The two computational guarantees have distinct scopes. Laurent extraction decides whether every compatible completion shares a finite standard part, including certified rejection. The elementary compiler proves a derivative and quotient identity under explicit domains, with symbolic output. It supplies neither complete elementary limit decisions nor reverse-mode differentiation. Arbitrary host-language control flow and tensor execution are also outside the differentiable language.

\section{Finite Observations and Classical Completion}\label{sec:background}

The formal semantics uses total real sequences, $\mathrm{Seq}=\N\to\R$, and their comparison sets. For $x,y\in\mathrm{Seq}$, write $L_{x,y}=\{n:x(n)<y(n)\}$ and $E_{x,y}=\{n:x(n)=y(n)\}$. A positive comparison observation selects its comparison set. A negative observation selects its complement. The family $\Gamma\subseteq\mathcal P(\N)$ records these actual selected sets, rather than Boolean names for them. The Lean definitions are \code{Sequence}, \code{comparisonLt}, \code{comparisonEq}, and \code{Commitments}.

A free ultrafilter $\PUF$ on $\N$ is a proper filter that decides every subset and contains no finite set. Equivalently, it extends the cofinite filter $\mathcal F_{\mathrm{cof}}=\{A\subseteq\N:A^c\text{ is finite}\}$. A completion of $\Gamma$ is such an ultrafilter containing every member of $\Gamma$. Lean's \code{Completion} records an ultrafilter, its extension of the cofinite filter, and containment of the commitments. \code{Extendible} asserts that a completion exists. This is an existence specification, not an algorithm constructing an ultrafilter.

The usual ultrapower interpretation identifies sequences $x$ and $y$ when $E_{x,y}\in\PUF$, yielding the hyperreal field $\R^\N/\PUF$~\cite{Robinson1966}. We use this interpretation to explain the observations and standard parts. The general project semantics formalizes sequence comparisons, filter limits, and completion properties. The worked quotient additionally uses Mathlib's hyperreal field. It does not reconstruct the whole ultrapower field or prove a new transfer theorem. Different completions can give different comparison answers to the same sequence representatives.

\begin{definition}[Free finite-intersection property]
  The family $\Gamma$ has the free finite-intersection property when every finite subfamily of $\Gamma\cup\mathcal F_{\mathrm{cof}}$ has nonempty intersection. The intersection of the empty family is $\N$. This is Lean's \code{HasFreeFIP}.
\end{definition}

\begin{theorem}[Completion criterion]\label{thm:completion}
  For any family $\Gamma\subseteq\mathcal P(\N)$,
  \[
    \operatorname{HasFreeFIP}(\Gamma)
    \quad\Longleftrightarrow\quad
    \operatorname{Extendible}(\Gamma).
  \]
  If $\Gamma$ is finite, these conditions are also equivalent to infinitude of its joint intersection $J_\Gamma=\bigcap_{A\in\Gamma}A$.
\end{theorem}
\begin{proof}
  A completion contains every finite intersection of commitments and cofinite sets. Such an intersection is nonempty because the filter is proper. Conversely, the free finite-intersection property makes the filter generated by $\Gamma\cup\mathcal F_{\mathrm{cof}}$ proper. The classical ultrafilter lemma extends it to an ultrafilter~\cite{Jech2003}. This extension is free: a finite member and its cofinite complement would otherwise have empty intersection.

  Now suppose $\Gamma$ is finite. If $J_\Gamma$ is infinite, intersecting it with any cofinite set leaves a nonempty set, which supplies the required finite-intersection property. If $J_\Gamma$ is finite, adjoining its cofinite complement to $\Gamma$ gives an empty finite intersection, contradicting that property.
\end{proof}

Lean proves the general equivalence as \code{hasFreeFIP\_iff\_extendible} and the finite-family characterization as \code{jointlyInfinite\_iff\_extendible}. Finiteness is a property of the executable observation traces, not a necessary hypothesis of the general completion theorem. Propositional satisfiability alone is insufficient: distinct atoms can denote disjoint actual sets even when their conjunction has a Boolean model. An implementation must connect its representations to these sets and preserve the semantic invariant.

\subsection{Standard Parts as Filter Limits}

For a sequence $x$, completion $\PUF$, and $c\in\R$, define
\[
  \operatorname{NearStandardAt}(\PUF,x,c)
  \quad\Longleftrightarrow\quad
  \forall\varepsilon>0,\ \{n:|x(n)-c|<\varepsilon\}\in\PUF.
\]
This says that $x$ converges to $c$ along $\PUF$. In the ultrapower interpretation, $x-c$ is infinitesimal and $c$ is the standard part of the represented hyperreal. Lean defines \code{NearStandardAt} with \code{Filter.Tendsto} and proves uniqueness as \code{nearStandardAt\_unique}.

\begin{proposition}[Ordinary limits are completion invariant]\label{prop:ordinary-limit}
  If $x(n)\to c$ ordinarily, then $\operatorname{NearStandardAt}(\PUF,x,c)$ for every free completion $\PUF$.
\end{proposition}
\begin{proof}
  For every $\varepsilon>0$, ordinary convergence makes $\{n:|x(n)-c|<\varepsilon\}$ cofinite. Every free completion contains this set.
\end{proof}

The Lean theorem is \code{cofiniteLimit\_completion\_invariant}, where \code{CofiniteLimit} denotes convergence along the cofinite filter. Its hypothesis must be proved for the actual sequence. The return of a numerical candidate does not establish it. The verified residue extractor below proves a support-relative version directly from exact finite coefficient checks. A successful result is shared by every completion consistent with the current observations. Failure to find a shared result need not mean that individual completions lack standard parts.

\subsection{A Choice That Remains Partial}

Let $a(n)=(-1)^n$. Initially both the even and odd index classes are infinite, so either comparison choice is compatible with a free completion. Every completion selects one parity, giving $a$ standard part $1$ or $-1$, but there is no common value across all completions. The verified extractor therefore returns \code{None} on universal support. Accepting $a<0$ retains the odd class. Extraction then returns $-1$ in every compatible completion, and an attempted commitment $a=1$ is rejected. Extraction itself makes no further choice.

The two observations $a<0$ and $a=1$ are individually realizable but select disjoint parity classes. Their conjunction could be satisfied if they were represented only by independent Boolean names, yet their actual sets admit no common completion. Lean proves this obstruction in \code{Counterexample}. This is why the executable state must represent the selected index sets and check their joint support.

Selecting the odd class does not make all sufficiently large indices odd, nor does it identify a unique ultrafilter. It requires only that the odd class belong to the completion. This distinction motivates the runtime: it retains all currently compatible residue alternatives and returns an invariant result when those alternatives agree, without computing a complete ultrafilter.

\section{Verified Periodic Laurent Core}\label{sec:verified-laurent}

\subsection{Syntax and Exact Normalization}

The executable grammar contains exact rational constants, $n$, $1/n$, finite periodic rational tables, addition, subtraction, multiplication, and division by an explicitly specified monomial $c n^k$, where $c\in\Q\setminus\{0\}$ and $k\in\mathbb Z$. A table $(b_0,\ldots,b_{p-1})$ denotes $b_{n\bmod p}$. $(-1)^n$ is the table $(1,-1)$. Validity checking rejects empty tables and zero divisor coefficients. The coefficient periods of expressions are combined by least common multiples. $n$ and $1/n$ have coefficient period one despite not being periodic sequences. On each residue of the resulting coefficient period, the normalizer produces
\[
  \frac{p(n)}{n^s},\qquad
  p(X)=a_0+a_1X+\cdots+a_dX^d,\quad a_i\in\Q,\ s\in\N.
\]
The numerator is a dense list of exact rational coefficients, evaluated by Horner's rule. Every coefficient is retained, including terms that a later division can shift into the constant term. There is no series truncation. The refinement theorem in \code{ResidueExpr} proves agreement with the source sequence at every positive index, including when residues are enumerated at a multiple of the expression's period. Lean's total inverse at index zero is irrelevant to free-ultrafilter semantics.

\subsection{Comparison Masks with Computed Cutoffs}

The executable sign recursion returns both a sign and a natural cutoff $K\ge1$. If a Horner tail has nonzero leading coefficient $r$ and cutoff $K$, adjoining the constant coefficient $a$ uses
\[
  K'=\max\!\left\{K,\left\lceil\frac{|a|}{|r|}\right\rceil+1\right\}.
\]
The proof maintains the tail's sign and a magnitude of at least $|r|$ at every real argument beyond the cutoff. Zero tails are handled separately, including representations with trailing zero coefficients. Division by $n^s$ preserves the sign for $n\ge K$. The comparison compiler applies this rule to the difference of two normalized forms on each residue of the operands' common period and takes the maximum cutoff. Thus the reported mask agrees with the actual comparison at every later index. No supplied correctness field or sampled evaluation substitutes for this proof.

\subsection{Support Refinement}

The state is a Boolean support table of positive length with at least one true entry. If its period is $p$ and a selected comparison mask has period $q$, the transition enumerates $\ell=\operatorname{lcm}(p,q)$ residues and computes
\[
  S'(r)=S(r\bmod p)\land M(r\bmod q),\qquad 0\le r<\ell.
\]
It accepts exactly when some entry remains true. The proved carrier identity $\operatorname{carrier}(S')=\operatorname{carrier}(S)\cap\operatorname{carrier}(M)$ shows that period growth preserves every prior commitment. A rejected transition leaves the API state unchanged. In particular, compatible choices modulo $2$ and $3$ can select one residue modulo $6$, whereas incompatible choices at periods with shared factors are rejected.

\subsection{Shared Standard Parts}

Standard-part extraction performs a separate, read-only check at the least common multiple of the support period and the queried expression's period. On each active residue, it requires every numerator coefficient above degree $s$ to vanish, then reads the coefficient of degree $s$ (zero if absent). It returns a rational only if these finite limits agree across all active residues. Inspecting the enlarged common period does not alter the stored support. Failure may mean divergence on an active branch or disagreement between branches. It need not mean that a standard part fails to exist in individual completions.

\begin{theorem}[Accepted traces and extracted standard parts]\label{thm:laurent-runtime}
  Let a finite trace $T$ be accepted from universal support, with final carrier $S_T\subseteq\N$, and let $\Gamma_T$ be the family of its actual selected comparison sets, using complements for negative choices. Then $\Gamma_T$ has a free completion, and for every free ultrafilter $\PUF$,
  \[
    S_T\in\PUF\quad\Longleftrightarrow\quad
    \forall A\in\Gamma_T,\ A\in\PUF.
  \]
  If extraction on $S_T$ returns $q\in\Q$ for an expression $e$, then $\lim_{\PUF}e(n)=q$ in every free completion of $\Gamma_T$.
\end{theorem}
\begin{proof}
  Each computed mask differs from its actual selected set only on a finite prefix, so the two sets have identical membership in every free ultrafilter. The carrier identity for least-common-multiple refinement and induction over accepted intersections give the displayed equivalence. A nonempty support of positive finite period is infinite, which supplies a free completion. Successful extraction proves the same ordinary limit for every active normalized form. There are finitely many such forms, so their eventual bounds can be combined and then specialized to the actual residue of each index in $S_T$. Restricting to any free ultrafilter containing $S_T$ preserves the resulting limit, and the equivalence applies it to every completion of the trace.
\end{proof}

The support and expression proofs are in \code{ResidueSupport} and \code{ResidueExpr}. Comparison correctness is in \code{ResidueComparison}. Transition, extraction, and trace proofs are in \code{ResidueRuntime}, \code{ResidueLimit}, and \code{ResidueTrace}. These reuse the scalar Laurent normalization, sign, and limit proofs. In particular, \code{run\_standardPart\_sound} concludes correctness for every completion of the recorded observations. Successful extraction on universal support also implies ordinary cofinite convergence.

\begin{theorem}[Completeness of shared extraction]\label{thm:extraction-completeness}
  Let $e$ be a valid expression and $S$ a nonempty residue support. For each $q\in\Q$,
  \[
    \sthat_S(e)=q
    \quad\Longleftrightarrow\quad
    \forall\PUF\supseteq\mathcal F_{\mathrm{cof}},\quad
      S\in\PUF\Longrightarrow\lim_{\PUF}e(n)=q.
  \]
  Moreover, if the limit is shared for any $r\in\R$, then $r$ is rational and the extractor returns it. A failed extraction therefore rules out every shared finite real value, not only the rational candidates searched by the implementation.
\end{theorem}
\begin{proof}
  Soundness was proved above. For the converse, each active residue of the support/expression common period is infinite and supports a free ultrafilter containing $S$. Restricting to that residue identifies $e$ with one rational Laurent form. A scalar Laurent form with a nonzero positive power of $n$ has unbounded absolute value along every free filter. Otherwise its limit is its rational constant term. A common finite limit consequently forces every active residue to have the same rational constant term, exactly the finite checks performed by the extractor.
\end{proof}

The declarations \path{standardPart_complete_real}, \path{standardPart_iff_all_completions}, and \path{standardPart_none_no_common_real} in \code{ResidueLimitCompleteness} prove the converse and its failure consequence. Validity and nonempty support are essential hypotheses. Invalid syntax is not a divergent sequence, and an empty set of completions would make a universal limit claim vacuous. The equivalence with trace completions in Theorem~\ref{thm:laurent-runtime} transfers completeness to accepted traces.

The executable diagnostic returns either the common rational, an active residue whose normalized form diverges, or two active residues with different finite limits. Residues are reported modulo the support/expression common period. A separate invalid-input result keeps malformed syntax and empty support distinct from mathematical failure. The declarations \path{standardPart_none_iff_diagnostic_failure}, \path{diagnoseStandardPart_divergent_completion}, and \path{diagnoseStandardPart_disagreement_completions} in \code{ResidueLimitDiagnostic} prove that these failure cases are exhaustive and exhibit compatible completions realizing them. The classification explains why a shared standard part is unavailable on the current support.

\subsection{Implementation Boundary}

The native \code{residue\_checker}, built from \code{ResidueChecker}, calls these same executable functions. The Python interface constructs expression trees and records observations. Ordinary native calls rely on faithful transport, JSON parsing, native compilation, and execution. The optional replay path below checks individual exported claims without trusting the native answer. The implementation enumerates its support tables explicitly, so they can grow to the least common multiple of introduced periods. No period minimization or general scalability guarantee is claimed.

\section{Adaptive Execution and Fixed Completions}\label{sec:programs}

A trace theorem explains a completed list of observations. To connect that theorem to control flow, \code{ObservationPrograms} defines a finite program tree. A leaf returns a residue expression. A query node contains a strict comparison or equality and two continuation programs. Later queries and the returned expression may therefore depend on earlier answers. The syntax describes finite decision trees, not arbitrary Python programs or unbounded loops.

The executable interpreter consumes a list of proposed Boolean answers. At each query it forms the actual observation, calls the verified residue commitment operation, and follows the selected continuation only if that commitment succeeds. Missing answers or rejected commitments cause execution failure. A leaf checks expression validity and nonempty support, then performs read-only standard-part extraction. An accepted execution may therefore have a leaf result of \code{None}. This is different from failing to execute the program.

The result records the selected trace, final support, leaf expression, extracted value, and unused proposed answers. These are data, not supplied proofs of consistency. The execution proof first shows that replaying the recorded trace with the residue transition function gives the recorded support. It then applies the established trace-to-completion theorem.

\begin{theorem}[Fixed-completion realization]\label{thm:program-realization}
  Suppose a finite program executes successfully from universal support. There exists a free ultrafilter $\PUF$ such that interpreting every comparison by membership of its actual comparison set in $\PUF$ follows the same branches and selects the same leaf expression. In fact, every free completion of the recorded trace selects that leaf. If the extracted value is $q\in\Q$, the leaf expression has standard part $q$ in every such completion.
\end{theorem}
\begin{proof}
  Induction on the executable program connects each accepted query to its recorded observation and its chosen continuation. The trace theorem supplies a free completion containing every selected observation. For a positive answer the comparison set belongs to that completion. For a negative answer its complement belongs, so the comparison set does not. A second induction therefore follows the same continuation at each node under the fixed ultrafilter interpretation. The support characterization and extraction theorem give the final standard part.
\end{proof}

The corresponding Lean declarations are \path{Program.execute_interpret}, \path{Program.execute_realized}, and \path{Program.execute_standardPart_sound}. Corollary~\ref{cor:adaptive-derivative} instantiates these declarations with an observation-dependent denominator obligation and proves a common result for every accepted input stream. Further kernel-checked examples exercise different later queries, rejected contradictory choices, exhausted choice streams, and accepted unknown outputs.

The quantifiers matter. Each accepted run admits a fixed completion. Incompatible alternative runs need not share one. Nor does the interpreter compute the completion used in the proof. Its proposed answers can come from a caller or search procedure, but acceptance depends on the semantic check. Only the visited queries and returned expression are validated. A common ordinary result across alternative runs requires an additional argument about their extracted values, as supplied by \path{accepted_result} in the domain example. Fixed-completion realization alone does not imply that all branches compute the same value.

For a continuing mathematical history, there is a related classical observation. If $\Gamma_0\subseteq\Gamma_1\subseteq\cdots$ and every $\Gamma_k$ has a free completion, then $\bigcup_k\Gamma_k$ has one free completion. Every finite subfamily of the union lies in a sufficiently late stage, giving the free finite-intersection property required by Theorem~\ref{thm:completion}. Lean proves this as \path{extendible_iUnion_of_monotone}. This is a compactness consequence of the completion criterion. It neither supplies an executable ultrafilter nor certifies future behavior from one finite snapshot. A running system needs an invariant covering every accepted step.

\section{Kernel Replay of Exported Sessions}\label{sec:replay}

The public API records the exact operand syntax, comparison operation, and selected truth value of each accepted commitment. Rejections and read-only probes do not enter this trace. An extraction snapshot freezes the accepted trace $T$, current support $S$, query expression $e$, and claimed result $v\in\operatorname{Option}(\Q)$. Later state changes do not alter it. The exported bundle contains exact rational JSON data, generated Lean declarations, and a manifest associating their hashes with the pinned proof sources.

The Lean structure \code{Residue.Replay.Snapshot} contains these data and no fields asserting their correctness. Its Boolean \code{check} requires a valid expression, nonempty support, and the two executable equalities
\[
  \operatorname{run}(\operatorname{universe},T)=\operatorname{some}(S),
  \qquad
  \operatorname{standardPart}(S,e)=v.
\]
For a closed exported snapshot $\sigma$, generated source proves $\operatorname{check}(\sigma)=\operatorname{true}$ using \code{decide +kernel}. The theorems \code{Snapshot.trace\_extendible} and \code{Snapshot.support\_mem\_iff} then establish existence of a compatible free completion and the exact final-support characterization. If $v=\operatorname{some}(q)$, \code{Snapshot.standardPart\_sound} yields the standard part $q$ in every completion of that actual exported trace. For $v=\operatorname{none}$, \path{Snapshot.no_common_standardPart} excludes a common finite real standard part, and \path{Snapshot.failure_classified} proves that the computed diagnosis is divergence or disagreement. Replay does not check the particular witness fields returned separately by the native diagnostic interface. Individual completions can still have standard parts, and later observations may select a value.

Verification regenerates fixed Lean syntax from validated snapshot data, checks artifact association, refreshes the imported build, and elaborates the regenerated source under a resource deadline. Every generated theorem has an axiom report. The accepted set is \code{propext}, \code{Classical.choice}, and \code{Quot.sound}. The replay uses neither \code{native\_decide} nor native evaluation as proof evidence: those shortcuts would add compiler trust beyond kernel reduction. The dependency libraries, their stated axioms, the Lean kernel, and the surrounding operating system and hardware remain part of the assurance assumptions.

For a successfully replayed claim, a wrong native answer cannot supply the checked equalities. Replay nevertheless proves a statement about the exported syntax, not that Python captured the intended expression or that the recorded observations occurred in an external process. Capture, wire-format mapping, and source-data association are tested implementation obligations. Hashes bind artifact components for checking. They do not authenticate the historical truth of the session. This distinction separates a kernel-checked mathematical instance from a formally verified end-to-end application.

\subsection{Validation of the Execution Boundary}

The integration tests exercise exact large rationals, terms retained through later division, changes of period, incompatible commitments, and extraction without mutation. Replay tests include malformed snapshots, invalid expressions claiming an unknown result, inconsistent final supports, altered artifacts, and incorrect native answers. In one regression, a mocked native checker reports $2$ for the constant expression $1$. Snapshot capture records that claim, but kernel replay rejects it. These tests check concrete interface behavior. The general all-indices and all-completions guarantees come from the Lean theorems, whose audited dependencies are restricted to the stated axiom set.

\section{Related Work}\label{sec:related}

Beeson~\cite{Beeson1995} used nonstandard analysis in Mathpert to justify symbolic calculus operations and proved correctness of an implemented infinitesimal-elimination procedure. His treatment also makes the side conditions of symbolic operations explicit. This is a close precedent for computational infinitesimals with correctness obligations. Our focus is the refinement of a finite support representing compatible completions through accepted observations, together with results that hold in every completion remaining after the trace.

Fleuriot and Paulson~\cite{FleuriotPaulson2000} constructed the hyperreals and mechanized nonstandard real analysis in Isabelle/HOL. Dou and Yu~\cite{DouYu2024} formalized the filter extension principle in Coq. Mathlib~\cite{mathlib2020} supplies filters, ultrafilters, limit theory, and a quotient construction of the hyperreals. Our development uses its filter and analysis infrastructure and states its semantic results for arbitrary compatible free ultrafilters. The mathematical existence of completions is established background. The implementation-specific obligation is to connect executable normalization, comparisons, state updates, and extraction to that semantics.

Nonstandard analysis also supports program semantics and verification. Benveniste et al.~\cite{Benveniste2012} give a nonstandard semantics of hybrid-system modelers, and Hasuo and Suenaga~\cite{HasuoSuenaga2012} investigate nonstandard static analysis of hybrid systems. Kido, Chaudhuri, and Hasuo~\cite{Kido2015} extend abstract interpretation with infinitesimals, proving soundness and termination under uniform widening and evaluating a prototype. The present artifact addresses a smaller expression language and an explicit finite observation trace. It does not provide a hybrid-system analyzer or a verified semantics for general programs.

Automatic differentiation~\cite{Griewank2008,Baydin2018} and computer algebra systems such as SymPy~\cite{Meurer2017} provide established ways to obtain derivatives. Our elementary compiler uses standard forward differentiation rules. Its role here is to connect their symbolic output to literal infinitesimal quotients whose denominator conditions can be established by finite observations. The additional guarantee concerns every completion compatible with an accepted trace. The polynomial compiler also connects these quotients to complete executable standard-part extraction. Neither result establishes a computational advantage over differentiation or symbolic algebra.

For the verified fragment, a support mask is an exact finite representation of the remaining residue alternatives. Intersection after lifting to a common period performs constraint refinement, so an ordinary finite-domain constraint solver can represent the same alternatives. The mathematical contribution of this representation is its proved correspondence with free-ultrafilter completions and the universal guarantee for a successfully extracted standard part.

Beeson and Wiedijk~\cite{BeesonWiedijk2005} use filters to give semantics to symbolic calculations with infinity, including partially informative outcomes and refinement. Their work is a direct precedent for interpreting calculations through filters. Our particular interface records accepted observations about index sets, proves that its finite executable states describe exactly the compatible free completions, and relates adaptive execution and extracted outputs to those completions.

Harrison and Th\'ery~\cite{HarrisonThery1998} separate external solution computation from formal checking in their integration of HOL and Maple. Kernel replay follows that established architecture. The statements checked here concern a recorded observation trace, its compatible completions, and a completion-invariant standard part. The general idea of checking an externally obtained symbolic result is not a novelty claim.

The contribution is the composition of three obligations: executable observations preserve a nonempty class of classical completions, one completion reproduces the control flow of each accepted adaptive run, and successful extraction is valid in every completion of that run. Completeness characterizes exactly when that ordinary value exists across all remaining completions. Generic polynomial differentiation, the elementary compiler, and the domain example connect this interface to literal infinitesimal quotients. The compiler rules themselves are standard differentiation rules. This combination makes the witness-free execution claim precise for the implemented language. It does not make finite-domain refinement, filter semantics, or infinitesimal differentiation new in themselves. Reusing the pattern with another non-constructive object would require a representation of finite observations, an executable consistency check connected to an extension theorem, and a sound extraction operation. The present artifact supplies one such instance, not a formal abstraction covering all such objects.

\section{Artifact Evidence and Boundaries}\label{sec:evaluation}

The main evidence is the Lean proof chain from executable observations to classical completions, adaptive execution, and standard-part extraction. The project audit rebuilds the development, rejects unfinished proofs and project-local axioms, and checks the reported dependencies of the maintained theorem roots. The allowed classical dependencies are \code{propext}, \code{Classical.choice}, and \code{Quot.sound}. The audit covers the residue algorithms, adaptive operational semantics, polynomial and elementary derivative compilers, and observation-dependent quotient theorems. The source-to-theorem links distinguish the general completion criterion, executable refinement, program realization, and the concrete calculus identity.

The artifact combines universal theorems with concrete replay. Polynomial differentiation covers arbitrary rational coefficients, rational points, nonzero rational scales, and positive integer step powers. Elementary differentiation covers every expression in its finite vector grammar on the stated smooth domains. Every accepted domain-program run establishes a nonzero denominator and returns $12$. Three saved snapshots check both branches and the absence of a common finite value before the observation. Supplementary forward and backward cubic snapshots exhibit distinct infinitesimal errors with the same standard part.

The proof boundaries are concrete. Complete extraction covers exact rational coefficients, finite coefficient periods, and monomial division. Representing an inverse on selected support does not implement complete rational-function normalization. The elementary derivative language supports general division and five elementary primitives on explicit smooth domains, but supplies no complete comparison or limit algorithm for them. Arbitrary sequence predicates remain outside both executable interfaces. Ordinary native calls assume faithful transport, parsing, compilation, and execution. Replay checks a regenerated mathematical instance, but faithful capture of the intended external computation remains unverified. The finite program syntax has no loops, and the Python API is not formally translated to it. Extraction completeness concerns values shared across every compatible completion, not the selection of a preferred completion.

The next boundary is faithful capture, richer observations, and efficient differentiation. A verified translation from the public API to finite program syntax would address capture. Complete residue extraction for general rational functions would require verified denominator checks and exact comparison and limit procedures. More general observations would likewise require executable checks with their own correctness arguments. The classical assertion that one consistent polarity exists does not supply such a procedure.

\section{Conclusion}

A finite computation can use infinitesimals through observations whose consistency has been checked, while its ultrafilter interpretation remains non-constructive. The executable state records the observations. The completion theorem supplies their classical interpretation. The program theorem shows that accepted adaptive execution is compatible with one fixed completion, and sound and complete extraction identifies exactly the finite values shared by all remaining completions.

Generic polynomial differentiation connects that interface to exact literal quotients and the ordinary derivative. The adaptive case makes the semantic obligation visible: an infinitesimal may be zero, so an observation must establish invertibility or cause the program to choose a different step. Both branches then extract the same ordinary value. The implementation never constructs the ultrafilter that justifies the selected execution. The elementary compiler extends the quotient guarantee to differentiable vectors with symbolic real outputs. Complete extraction remains specific to the periodic Laurent language. Faithful capture, broader observations, and efficient derivative execution remain to be established.
